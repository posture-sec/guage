Rule catalog

Sixteen checks. Four shipped.

Every rule has a stable kebab-case ID, a written condition and a severity. A finding names the rule, the account, an evidence line and a fingerprint that identifies it. An accepted risk matches on rule and account, not on the fingerprint.

The four live rules

These are registered in internal/rules, covered by positive and negative fixture cases, and exercised end to end by the CLI tests.

acct-missing

HIGH Live

A requested account returned 404. The endpoint answered, so this is a statement about the account, not about the network. The account may never have been created, or it may have been merged into another account. The run continues and reports the other accounts.

Evidence
endpoint URL returned not found
Acceptable
No. An acceptance cannot hide a missing account.
Exit effect
HIGH fails the default --fail-on high and produces exit 1.

acct-network-mismatch

HIGH Live

The endpoint's network passphrase differs from the network the run requested. No account is fetched from that endpoint at all, because an account ID can exist on more than one network and the report would describe the wrong chain. Each requested account is listed as skipped with this finding.

Evidence
expected Test SDF Network ; September 2015, endpoint reports Public Global Stellar Network ; September 2015
Acceptable
No.
Exit effect
HIGH fails the default threshold and produces exit 1. The run did not read an account, but it did complete and name the disagreement.

flag-drift

WARN Live

A flag the policy declares disagrees with the chain. Only declared flags are compared, so an omitted flag can never drift. The comparison runs in a fixed order: auth_required, auth_revocable, auth_immutable, clawback. The evidence lists each disagreement.

Example
auth_required declared false, observed true
Acceptable
Yes, with a reason and an optional expiry. The owner adds accept entries.
Exit effect
WARN is below the default --fail-on high. It produces exit 1 only under --fail-on warn.

flag-undeclared-clawback

WARN Live

Clawback is enabled and the policy says nothing about clawback. A declared value, true or false, suppresses this rule: declared true is a declaration, and declared false that disagrees with the chain is flag-drift instead.

Evidence
clawback observed true, and no clawback expectation is declared
Acceptable
Yes, with a reason and an optional expiry.
Exit effect
WARN. Exit 1 only under --fail-on warn.

What is not shipped

The twelve specified rules are a contract for the next phases, not behavior you can rely on today. The signer and threshold rules wait on threshold semantics that task 0.7 could not verify without submitting a transaction, which Gauge forbids itself to do. The identity rules wait on the guarded SEP-1 fetcher. Role-based severities are task 3.4.

Read the status before trusting a pass. A run evaluates the four rules above. A clean result means those four agreed with your policy; it says nothing about signers, thresholds, home domain or any rule marked Specified.
