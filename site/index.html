Stellar account posture / read-only

The chain knows. Your policy should too.

Gauge reads an account's signers, thresholds and flags, compares them with what you declared, and exits nonzero when they disagree. It never holds a key, never builds a transaction, and treats every downloaded value as hostile.

The comparison

Two inputs. One result.

Gauge is a state comparison, not a scanner. It needs something to compare against, and it says so when that something is missing.

Declared

Your gauge.toml: the account's role, expected signers, thresholds, flags and home domain.

  • role = "treasury"
  • expected_signers = [...]
  • expected_flags = { ... }
Compare

Observed

A snapshot fetched through Horizon, decoded strictly and sanitized before it reaches any output.

  • network passphrase
  • signers and weights
  • thresholds and flags

A disagreement becomes a finding with a stable rule ID, a severity, an evidence line and a fingerprint. An accepted risk matches on rule and account; the fingerprint is a stable identifier for the finding.

Scope

What Gauge reads

Public ledger state, through one Horizon endpoint, plus the stellar.toml an account's own home domain publishes, fetched under an address guard. No other host is dialed, no response body is logged, and a report quotes a document only through the identity fields it recognized, sanitized.

Signers
Who can sign, and with how much weight. The master key is a signer like any other, and sponsored signers are named.
Thresholds
How much weight each operation tier requires. Low, medium and high thresholds are read as stored, and the report also prints what they mean: the minimum number of signatures each tier needs, computed by the same function the rules call.
Flags
What the issuer enabled. Authorization required, revocable, immutable and clawback are compared only where the policy declares a value.
Home domain
The identity the account points at. Printed as a fact and fetched under a dial-time address guard: the published stellar.toml is parsed, the identity fields it recognized are printed as facts, and an identity Gauge could not verify is a warning rather than a pass.

acct-missing

The endpoint answered 404. The account was never created, or it was merged. HIGH, and it cannot be accepted.

acct-network-mismatch

The endpoint's passphrase differs from the requested network. No account is read. HIGH, and it cannot be accepted.

Live

flag-drift

A declared flag disagrees with the chain. Only declared flags are compared. WARN, and HIGH for an issuer.

Live

flag-undeclared-clawback

Clawback is enabled and the policy does not declare it. WARN, and HIGH for an issuer.

Live

sig-threshold-unreachable

A threshold tier the account's own signers can never reach, so that tier can never authorize. HIGH, and it cannot be accepted: SetOptions validates ranges, so the ledger stores this state rather than refusing it.

Live

sig-no-signing-weight

No signer above weight zero other than a pre-authorized transaction hash, so nothing on the account can authorize an operation again. HIGH, and INFO for an issuer that declares expect_locked.

Live

sig-hashx

A hash(x) signer is a shared secret, and spending it puts the preimage in a published envelope. WARN, and HIGH when that entry's own weight reaches the medium tier.

Live

id-no-home-domain

A declared home domain the chain does not show is a WARN, and an issuer that publishes nothing raises it with no declaration behind it.

Live

id-toml-unreachable

The published stellar.toml could not be fetched or parsed under the guard, or was observed and never fetched. WARN. The evidence names the step and quotes no body.

Live

id-toml-account-unlisted

A readable stellar.toml does not name this account in ACCOUNTS. WARN. Entries that are not account addresses are counted, never echoed.

Ten of the sixteen, chosen for what they prove about control. The full catalog, including the five rules that only fire against a declaration and the identity rule an issuer role raises without one, is on the rules page.

The boundary

A clean report is a posture result, not proof that the account cannot be compromised. Every report footer

Gauge cannot see who holds a key, whether signers are separate people, or what happens off-chain. It does not audit transactions, balances, offers, claimable balances, liquidity pools or Soroban contracts. It never describes an account as secure or safe.

Run it from source

There is no tagged release yet. The repository is the install path.

Shell
git clone https://github.com/posture-sec/guage
cd guage
go run ./cmd/stellar-gauge check \
  --network testnet \
  --endpoint https://horizon-testnet.stellar.org \
  G...

Requires Go 1.27.3. The first command reads one account and exits 0, 1, 2 or 3. Guides for check, audit and CI.

Gauge is functional alpha and unaudited. It reports posture against your declarations, never a guarantee. Read the status and limits before relying on a result.
